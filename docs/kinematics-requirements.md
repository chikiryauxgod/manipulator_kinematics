# Требования к расширению библиотеки кинематики

Зафиксировано 11 октября 2026 года. Этот документ отражает согласованные изменения требований к C11-библиотеке и имеет приоритет над прежним ограничением «только прямая кинематика». Реализована прямая кинематика; описанные ниже расширения ещё не реализованы.

## Задачи и модель

- Сохранить прямую кинематику: координаты суставов преобразуются в положение и ориентацию инструмента.
- Добавить позиционную обратную кинематику: вход — целевая точка инструмента `x, y, z` в мировой системе; выход — координаты суставов. Ориентация инструмента не ограничивается.
- Количество суставов задаётся при начальной настройке модели. Поддержать настраиваемые последовательные цепи, включая 3/4/5/6 суставов. Число суставов само по себе не гарантирует достижимость точки.
- Каждый сустав имеет одну независимую координату: угол для вращательного или перемещение для поступательного. Фиксированные преобразования базы и инструмента не добавляют степеней свободы.
- Геометрия каждого сустава задаётся стандартными DH-параметрами: тип, `a`, `alpha`, `d_offset`, `theta_offset`. Размеры — метры, углы — радианы.

## Обязательная настройка

Количество суставов, геометрия всех суставов, преобразования базы и инструмента должны быть заданы явно. Единичное преобразование и нулевые DH-параметры являются допустимыми значениями, поэтому готовность нельзя определять по ненулевым значениям полей.

Для каждого сустава задаётся конечный диапазон `q_min <= q_max` либо явно выбирается режим без ограничений. Единицы диапазона совпадают с единицами координаты сустава. Отсутствие диапазона не означает режим без ограничений. Диапазоны берутся из конструкции или паспорта робота; универсального диапазона для всех манипуляторов нет.

После задания параметров модель проходит проверку и переводится в готовое состояние. Попытка расчёта с неполной или недопустимой конфигурацией возвращает ошибку без изменения результата. Изменённая конфигурация должна пройти повторную проверку перед расчётами.

Для обратной кинематики явно задаются позиционный допуск и максимальное число итераций. Их численные значения и дополнительные параметры метода пока не выбраны.

## Поиск решения и диагностика

- Каждый вызов обратной кинематики получает начальное приближение — координаты всех суставов. Приложение может использовать текущее положение робота.
- Успех означает, что найденные координаты удовлетворяют ограничениям, а ошибка позиции, проверенная прямой кинематикой, не превышает заданного допуска.
- Одна точка может иметь несколько решений. Начальное приближение задаёт старт поиска; гарантия ближайшего или единственного решения не вводится.
- Ошибки конфигурации, входных данных, недостаточного буфера, численного расчёта и несходимости различаются.
- Исчерпание итераций не доказывает недостижимость. Отдельная ошибка недостижимости допустима только при обоснованной проверке для данной модели.
- На ошибке выходные координаты сохраняются. Рабочий буфер может содержать промежуточные данные и не является результатом.

## МК и RTOS

Ядро остаётся на C11, без динамического выделения памяти, зависимости от ОС, UART, блокировок и изменяемого глобального состояния. Память модели, результата и рабочего буфера предоставляет приложение; необходимые размеры должны быть доступны до расчёта.

Расчёты выполняются из задачи RTOS. Приложение обеспечивает согласованный снимок входных данных, период вызова, обмен результатами и синхронизацию. Неизменяемую готовую модель можно разделять между задачами; выходы и рабочие буферы у параллельных вызовов отдельные. Ограничение итераций не заменяет измерения времени исполнения на выбранном МК.

Связь с платой предполагается по UART. Modbus RTU обсуждался как вариант; окончательный протокол и карта данных ещё не выбраны. Транспортный адаптер остаётся вне математического ядра.

## Соглашение об именах

- Префикс публичного API — `k_`, констант и параметров сборки — `K_`.
- В коде координаты суставов называются `joint_positions`; для начального приближения — `initial_joint_positions`. Названия счётчиков и выходов должны явно указывать их назначение.
- В математических формулах сохраняется общепринятое обозначение `q`. Название `joint_positions` применимо и к углам, и к линейным перемещениям.
- Переименование существующих параметров и реализация новых функций выполняются отдельно; этот документ не объявляет их уже реализованными.

## Основание в пособии

[Пособие ИТМО](Modelirovanie_i_upravlenie_dvizheniem_robotov_-_ITMO.pdf): §1.1.2, печатная с. 17 (страница PDF 18) описывает обратную кинематику и неоднозначность решения. С. 54 рекомендует обращаться к паспортам манипуляторов. На с. 56 (страница PDF 57) приведён пример `robot.links[i].qlim = [-3.14, 3.14]`; это пример задания ограничений, а не общий аппаратный предел. Позиционная задача без ограничения ориентации — согласованное требование проекта.

## Проверка реализации

GoogleTest проверяет настройку и её полноту, пределы суставов, прямую проверку найденного решения, сохранение выхода на ошибке и поведение при исчерпании итераций. pytest проверяет новый API через собранный CMake потоковый бинарник. Оба численных профиля, цепи 3/4/5/6 суставов, разные начальные приближения и недостижимые контрольные цели входят в проверки. Контрольные геометрии должны иметь независимые эталонные решения.
