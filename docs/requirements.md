# Требования к учебной программе

Статус: требования к полноценной учебной работе. Основание — [пособие ИТМО](Modelirovanie_i_upravlenie_dvizheniem_robotov_-_ITMO.pdf), включая кинематику, динамику, планирование и управление, с [картой применимости](theory.md). Детали динамического контура приведены в [dynamics.md](dynamics.md). Код программы пока не реализован. [План работ](evolution.md), [архитектура](architecture.md), [правила C++17](cpp17.md).

## Что требуется по заданию

Написать программу для манипулятора с количеством звеньев от 3 до 6. Пользователь задаёт конечную точку, программа находит положения суставов, при которых конец манипулятора достигает этой точки. Конфигурация промежуточных звеньев произвольна. Координаты разрешено задавать через консоль либо статически в начале программы.

Минимальная часть задания — обратная кинематика по позиции. Расширенный вариант работы включает построение динамической модели, планирование движения, регулятор и численное моделирование замкнутой системы. Ориентация последнего звена для первого сценария остаётся свободной; она добавляется только если выбранная схема и формулировка цели этого требуют.

В приведённом тексте не определены плоская/пространственная модель, типы суставов, геометрия и необходимость физической сборки. Пособие описывает пространственную кинематику, но не уточняет индивидуальное условие сдачи. Его приложение А содержит отдельный расширенный курсовой проект; автоматически переносить его объём в это задание нельзя.

## Рабочие решения проекта

- Язык — C++17, уже выбранный в проекте. Обязательная версия исполняется локально; возможный [профиль МК](embedded.md) использует то же ядро без ROS.
- Для расширяемости модель поддерживает последовательную цепь из 3–6 вращательных суставов. Один сустав на звено — принятое упрощение; число суставов явно хранится в модели.
- Рабочая модель — пространственная, цель задаётся как x/y/z. Плоская цепь является частным случаем с фиксированной плоскостью. Это проектное допущение, а не установленное требование преподавателя.
- Демонстрационная геометрия задана в [model.md](model.md): базовая пространственная 3R-цепь и расширения до 6R. Используется стандартная DH-конвенция; база, инструмент, смещения нулевых углов и единицы явны. Это выбранный пример, не копия модели из пособия.
- Программа предлагает консольный ввод и встроенный пример. По заданию достаточно одного способа; второй добавляется как небольшой удобный режим.
- Результат расширенной работы — проверенная модель, траектория, управляющее воздействие и графики ошибки, скоростей и моментов. Физическое перемещение не заявляется: сначала выполняется численная симуляция.
- Для динамики задаются массы, центры масс, тензоры инерции, инерции приводов, редукторы, вязкое и кулоново трение, ограничения суставов. Значения обосновываются паспортом либо явно принимаются как учебные допущения.

Численные пределы — начальные проектные настройки, а не условия преподавателя и не результаты измерений. Их изменение сопровождается проверкой контрольных целей. Общее время решения измеряется для демонстрационной модели; требование жёсткого real-time отсутствует.

## Границы математических гарантий

Численный решатель может не найти решение для достижимой точки. Превышение числа итераций означает no_convergence, а не unreachable. Статус unreachable допустим лишь при доказанной геометрической проверке, например если расстояние до основания превышает консервативную сумму норм фиксированных смещений с учётом базы и инструмента. Для конкретной демомодели используются более точные границы из model.md. Обратное неверно: попадание в этот шар не гарантирует достижимость.

Для произвольной пространственной 3R-цепи нельзя обещать достижение любой x/y/z. Набор достижимых точек зависит от геометрии. Выбранная демомодель имеет конкретную рабочую область, описанную в model.md. Проверка полного шестимерного положения и ориентации не подменяет позиционную задачу.

## За пределами сдачи

Веб-интерфейс, MQTT, OPC UA, ROS 2, промышленные шины, несколько роботов, БД, ML и функциональная безопасность реального оборудования не являются требованиями этой учебной программы. Они сохранены в [каталоге будущего развития](technologies.md). Modbus RTU по RS-232 предусмотрен как отдельный этап переноса на МК, не зависимость локальной сдачи. Реальная сборка добавляется только после подтверждения условий задания; консольный вывод углов не заменяет управление приводами.

## Соответствие пособию

Используются §1.1.1 (стандартные DH и FK), §1.1.2 (неоднозначность ОЗК), §1.1.3 (якобиан и сингулярности), §1.2 (динамика), §1.3 (планирование) и §1.4 (управление). На с. 20 отмечена перестановка формул R/P, поэтому обязательна FR-11. DLS — выбранное численное дополнение к теории. Python/Corke Robotics Toolbox из пособия можно использовать для независимой сверки, но язык основной программы остаётся C++17. Формат отчёта выбирается по требованиям преподавателя; полный ГОСТ-отчёт и лабораторный `.ipynb` добавляются, если они назначены явно.
