# Валидация версии разработки 0.1.0

Проверки выполнены локально на Linux x86-64. Это результаты вычислений и интеграции в указанном окружении, а не физическая точность манипулятора. Workflow в [.github/workflows/ci.yml](../.github/workflows/ci.yml) подготовлен, но удалённый запуск пока не выполнен.

## Проверки

| Набор | Результат |
| --- | --- |
| GoogleTest: GCC/Clang × Debug/Release × float/double | 35 тестов в каждой из 8 сборок, все прошли |
| ASan/UBSan | Clang Debug unit-тесты обоих профилей прошли |
| pytest с обязательным embedded | 131 тестов, все прошли, без skip |
| Потоковые pytest с ASan/UBSan | 106 тестов, оба профиля, все прошли |

Тесты проверяют математические результаты, отрицательные входы, сохранение выходов, алиасинг композиции, ёмкости буферов, интерфейс C/C++, установку/перемещение пакета и внешних потребителей, запрет fast-math, несовместимость ABI-профилей. Потоковый драйвер проверяется отдельным процессом через stdin/stdout: несколько запросов, интерактивный ответ до EOF, фрагменты, LF/CRLF, строгая грамматика и восстановление после ошибок. Предел строки 64 KiB проверяется на границе.

Для Cortex-M4 построены и выполнены полноценные ELF обоих профилей, проверены отсутствие allocator/I/O-зависимостей ядра и отчёты стека. Отсутствующие embedded-инструменты при `--embedded` приводят к ошибке; при обычном host-запуске этот набор пропускается явно.

Дополнительно прошла Release-сборка с CMake 3.28.3 и `-Wall -Wextra -Wpedantic -Werror`: 35 unit-тестов, пример и численный отчёт.

Локальное окружение: GCC 13.3.0, Clang 18.1.3, CMake 3.30.3, GoogleTest 1.14.0, pytest 7.4.4; Arm GNU GCC 13.2.1, newlib 4.4.0, QEMU 8.2.2. CI-версии контейнера и инструментов закреплены в [lock-файле](../ci/test-toolchains.lock); зависимости готовятся отдельно от CMake.

## Численные результаты

Проверены размеры 1, 3, 4, 5, 6, 7, 16, 64, пространственные и смешанные R/P-цепи, знаковые DH-параметры, смещения, база и инструмент. Эталоны включают ручные аналитические случаи и независимый расчёт мировых базисных векторов в long double. Эталон не вызывает функции ядра и не собирает его DH-матрицы. Проверяется каждый кадр.

Максимальные наблюдаемые ошибки относительно эталонов в GCC-сборках:

| Профиль | Позиция, м | Максимальная ошибка элемента вращения |
| --- | --- | --- |
| double | 2.453159203552601753e-14 | 1.564612155113831449e-15 |
| float | 2.170818821222364123e-05 | 9.669948531228732269e-07 |

Позиция проверяется с масштабом модели S и абсолютным/относительным допуском из раздела 8 [архитектуры](c11-architecture.md); допуски не изменялись ради результатов. Эти числа характеризуют выбранный набор, не верхнюю оценку для любой геометрии. Для n=1024 разрешён корректный результат либо контролируемая численная ошибка; он не входит в область гарантированной точности. Проверены большие углы, субнормальные значения и отказы при переполнении.

GoogleTest записывает максимумы в XML. Сводку можно получить командой:

```sh
python3 ci/numerical_report.py build-tests/gtest-results
```

## Память Cortex-M4

MPS2 AN386, software floating point, Release, Arm GNU/newlib. Данные всего smoke ELF:

| Профиль | text, байт | data, байт | bss, байт | Измеренный стек при n=3/6/64, байт |
| --- | --- | --- | --- | --- |
| double | 17424 | 0 | 19968 | 1532 / 1532 / 1532 |
| float | 13800 | 0 | 9984 | 768 / 768 / 768 |

text включает startup, тестовый адаптер и достижимую часть libm. bss включает статические таблицы модели, q и оба массива кадров на 64 сустава. Резерв стека 16 KiB в linker script не входит в эти bss-числа. Измерение watermark включает вызывающий smoke-код, математический runtime и запас 256 байт при окрашивании: это наблюдаемая оценка использованной области тестового стека, а не точный размер одного вызова ядра. Проверка сравнивает одинаковый сценарий при разных n; роста с длиной цепи не обнаружено. Отчёты `-fstack-usage` дополнительно подтверждают статические кадры функций ядра.

`sizeof(mk_transform)` равен 128 байт для double и 64 для float в проверенном окружении. Два буфера кадров при n=6 занимают 2048 или 1024 байта соответственно. Они выделяются приложением и не входят во внутренний стек библиотеки.

## Воспроизведение

Команды host-тестов приведены в [README](../README.md), cross-сборки — в [embedded-инструкции](../tests/embedded/README.md). Полный интеграционный прогон сохраняет результаты:

```sh
python3 -m pytest --embedded --basetemp=build-integration \
  --junitxml=build-integration/results.xml -q
CC=clang CXX=clang++ python3 -m pytest tests/integration/test_forward_stream.py \
  --sanitizers -q
```

Каталоги `build-*` исключены из Git. Внутри результатов cross-тестов находятся ELF, map, size.txt, qemu-result.txt со строками STACK и отчёты .su; workflow сохраняет их как артефакты. Unit-отчёты находятся в gtest-results соответствующей сборки.

Не проверены реальные платы, время расчёта/WCET, Windows/MSVC и другие архитектуры. Версии критических CI-пакетов закреплены, но непрямые apt-зависимости не являются полностью герметичным архивом. Лицензия и внешняя поставка остаются отдельными незавершёнными задачами.
