# Правила реализации C++17

Область: обязательная [учебная программа](requirements.md). Правила применяются к собственному коду; будущий профиль микроконтроллера уточнён в [embedded.md](embedded.md).

## Типы и контракты

- C++17 без compiler extensions; не использовать std::span, std::jthread и std::expected как доступные в этом стандарте.
- Именованные типы RobotModel, JointAngles, TargetPosition, SolveOptions, SolveResult; размеры данных проверяются на границе библиотеки.
- Внутри библиотеки метры и радианы. Единицы указываются в именах параметров или документации, градусы преобразуются только при вводе/выводе.
- Проверять конечность чисел, размеры, DH-параметры, преобразования базы/инструмента и настройки поиска. assert не заменяет проверку внешних данных.
- Ожидаемый отказ решателя возвращается типизированным статусом; успешность не определяется наличием массива углов.
- Не вводить универсальную иерархию ошибок. std::optional используется для отсутствующих данных; enum class — для статусов.

## Владение и зависимости

- Для модели до 6 суставов использовать фиксированные массивы и матрицы, явный workspace и отсутствие выделений памяти внутри solve; размер прошивки/стека проверяется на выбранном МК.
- Владение значениями и RAII; сырые ссылки не владеют объектами. Динамический полиморфизм используется только при реальной необходимости.
- Нет mutable globals, singleton модели, service locator и DI-framework. Модель и настройки передаются аргументами.
- Математическая библиотека не читает stdin, не печатает stdout и не включает HAL/UART/Modbus. Тип float вместо double выбирается только после проверки точности.
- Для МК расчёт разбивается на ограниченные шаги; ISR только обслуживает ввод/вывод, не решает IK. Поддержка сборки core без исключений/RTTI проверяется выбранным toolchain.
- Модель, FK и IK имеют отдельные ответственности; применение SOLID описано в архитектуре.
- Один поток достаточен. Параллелизм не добавляется до появления независимой задачи и измеренной необходимости.

## Численная реализация

- Не вычислять явную обратную матрицу для шага DLS; использовать решение линейной системы.
- Проверять статус решения системы и конечность промежуточных/выходных значений.
- Допуски, damping и пределы поиска находятся в настройках, не разбросаны по исходникам.
- Не сравнивать вещественные позиции точным равенством. Успех определяется нормой ошибки относительно допуска.
- Псевдослучайность имеет фиксируемый seed. Лучшее приближение не выдаётся за точное решение.

## Сборка и проверка

- Targets manipulator_kinematics и manipulator_cli; зависимости задаются через target_link_libraries, без глобальных include_directories.
- Публичные заголовки самодостаточны; нет using namespace в заголовках.
- Согласованные имена: типы PascalCase, функции/переменные/файлы snake_case, namespace manipulator.
- Предупреждения -Wall -Wextra -Wpedantic для собственного кода; сторонние зависимости не переписываются ради них.
- CTest проверяет стандартную DH-матрицу, независимые примеры FK, якобиан через центральные разности, решения IK и отказы. Сравнивается достигнутая точка, а не единственный набор углов.
- При появлении кода выполнить доступную сборку и тесты; sanitizers использовать для поиска ошибок памяти/UB, если поддерживает окружение.
- Форматирование единообразно; версия математической зависимости и команды сборки записаны в README.

Исходники и настроенные проверки пока отсутствуют; этот документ задаёт правила их создания.
