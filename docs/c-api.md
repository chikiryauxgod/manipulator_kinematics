# Руководство C API

Версия разработки 0.1.0. Публичные заголовки находятся в [include/manipulator](../include/manipulator/). `config.h` генерируется CMake для выбранного профиля. Код приложения включает `<manipulator/forward.h>` и при необходимости `<manipulator/transform.h>`.

## Геометрия и системы координат

`manipulator_real` — double по умолчанию, float при `MANIPULATOR_REAL_TYPE=float`. Длины измеряются в метрах, углы — в радианах. Сустав `manipulator_dh_joint` содержит тип, `a`, `alpha`, `d_offset`, `theta_offset`. Используется стандартная DH-конвенция:

`A_i = Rz(theta_i) Tz(d_i) Tx(a_i) Rx(alpha_i)`.

Для `MANIPULATOR_REVOLUTE`: `theta_i = theta_offset + q[i]`, `d_i = d_offset`. Для `MANIPULATOR_PRISMATIC`: `theta_i = theta_offset`, `d_i = d_offset + q[i]`. Modified DH не поддерживается. Знаковые длины допустимы; ограничения хода и столкновения проверяет приложение.

`manipulator_transform.m[4][4]` хранится построчно и преобразует столбец координат из дочерней системы в родительскую. Последний столбец — перенос, верхний блок 3×3 — вращение. Последняя строка должна быть точно `(0, 0, 0, 1)`. Результат:

`world_tool = world_base * A_1 * ... * A_n * last_tool`.

## Модель и владение памятью

`manipulator_model_init(out, joints, n)` проверяет таблицу и сохраняет указатель на неё, устанавливает единичные `world_base` и `last_tool`. Число суставов положительное; фиксированного предела 6 или 64 в ядре нет. Размеры, которые невозможно безопасно представить, отклоняются. `manipulator_model_validate(model)` проверяет таблицу и оба преобразования.

Массив суставов остаётся собственностью приложения и должен жить дольше всех вызовов с этой моделью. Инициализация не копирует таблицу и не создаёт кэш. Базу и инструмент можно присвоить после инициализации. Каждый расчёт повторно проверяет модель.

При параллельных вызовах модель и входные массивы должны оставаться неизменными, выходы и workspace должны быть отдельными для каждого вызова. Ядро не содержит изменяемого глобального состояния. Пересечение входных и выходных областей запрещено, кроме явно разрешённого случая композиции ниже. Ёмкости измеряются в элементах, не в байтах; действительный размер и время жизни памяти обеспечивает вызывающий код.

## Функции

| Функция | Действие |
| --- | --- |
| `manipulator_transform_identity(out)` | Записывает единичное преобразование |
| `manipulator_transform_validate(transform)` | Проверяет конечность, вращение и последнюю строку |
| `manipulator_transform_compose(parent_mid, mid_child, out)` | Вычисляет произведение; `out` может точно совпадать с любым входом |
| `manipulator_model_init(out, joints, joint_count)` | Создаёт модель с единичной базой и инструментом |
| `manipulator_model_validate(model)` | Проверяет модель без изменения данных |
| `manipulator_forward(model, q, q_count, world_tool)` | Вычисляет одну позу инструмента |
| `manipulator_forward_frames(model, q, q_count, frames, frame_capacity, workspace, workspace_capacity)` | Вычисляет все кадры через рабочий буфер |

`q_count` должен равняться `joint_count`. Для кадров нужны **два непересекающихся массива по n+2 преобразования**: выход и workspace. Индексы результата: `0` — база в мире, `1..n` — звенья в мире, `n+1` — инструмент в мире. Элементы за `n+2` не изменяются.

Все функции, записывающие выход, сохраняют его при ошибке. При численном отказе `workspace` может содержать частичный расчёт: это не результат. После проверки входов расчёт занимает O(n) времени и O(1) внутренней памяти. Для всех кадров внешняя память занимает `2*(n+2)*sizeof(manipulator_transform)` байт. Для одной позы рабочий массив не нужен.

Рабочий [пример](../examples/forward_example.c) вызывает обе FK-функции, проверяет статусы и использует массивы фиксированного размера.

## Статусы

| Статус | Код | Значение |
| --- | --- | --- |
| `MANIPULATOR_OK` | 0 | Успех |
| `MANIPULATOR_INVALID_ARGUMENT` | 1 | Обязательный указатель равен NULL |
| `MANIPULATOR_INVALID_MODEL` | 2 | Недопустимое число или тип суставов |
| `MANIPULATOR_SIZE_MISMATCH` | 3 | Число координат не совпадает с моделью |
| `MANIPULATOR_BUFFER_TOO_SMALL` | 4 | Недостаточная ёмкость frames или workspace |
| `MANIPULATOR_NONFINITE_INPUT` | 5 | Вход содержит NaN/Inf |
| `MANIPULATOR_NUMERIC_ERROR` | 6 | Переполнение или недопустимое вычисленное преобразование |
| `MANIPULATOR_INVALID_TRANSFORM` | 7 | Конечная входная матрица не удовлетворяет контракту преобразования |

Если нарушено несколько условий, порядок выбора ошибки не входит в API. Статус возвращается непосредственно, без протокола через errno и без печати сообщений. Контракт рассчитан на quiet NaN; обработка signaling NaN не обещается.

## Численный профиль и переносимость

Нужны IEEE binary32/binary64, округление к ближайшему, сохранение субнормальных чисел и обычный runtime libm без включённых ловушек floating point. Запрещены fast-math и finite-math-only; обнаруживаемые флаги отклоняются при сборке. Режимы FTZ/DAZ должен отключить вызывающий проект. Ограничения нельзя проверить только размерами C-типов; host-тесты и embedded-smoke проверяют выбранное окружение.

Допуск проверки вращений — `2e-12` для double и `2e-5` для float; он не применяется к последней строке. Матрицы не нормализуются автоматически. Длинные цепи могут завершиться контролируемой численной ошибкой из-за накопления округления. Диапазон математического runtime и точность сокращения аргументов ограничивают работу с огромными углами. Область проверенной точности описана в [валидации](validation.md).

Публичные имена функций отображаются через config.h на символы `manipulator_v1_f64_*` или `manipulator_v1_f32_*`. Используйте заголовки выбранной сборки: смена `MANIPULATOR_USE_FLOAT` в приложении запрещена. Каждый профиль устанавливается в отдельный prefix, поскольку config.h и имя импортируемого target общие. Одновременное подключение двух профилей в один процесс пока не поддерживается. ABI разных компиляторов и платформ не гарантируется; структуры не являются форматом сериализации.

Для собственной embedded-сборки нужны четыре файла `src/*.c`, их внутренний заголовок, публичные заголовки и config.h выбранного профиля; C11, libm и memcpy предоставляет toolchain. Startup, linker script и реакция на ошибку принадлежат приложению. Ядро не требует GoogleTest, C++, Python, POSIX или heap.
