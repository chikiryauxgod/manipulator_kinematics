# Руководство C API

Версия разработки 0.2.0, ABI 2. Публичные заголовки находятся в [include/manipulator](../include/manipulator/). `config.h` генерируется CMake для выбранного численного профиля. API доступен из C11 и C++ через `extern "C"`.

| Заголовок | Назначение |
| --- | --- |
| `<manipulator/types.h>` | Численный тип, структуры и статусы |
| `<manipulator/model.h>` | Поэтапная настройка и проверка модели |
| `<manipulator/transform.h>` | Единичное преобразование, проверка и композиция |
| `<manipulator/forward.h>` | Прямая кинематика: поза инструмента и все кадры |
| `<manipulator/inverse.h>` | Позиционная обратная кинематика, параметры и отчёт |

## Геометрия и системы координат

`k_real` — double по умолчанию, float при `K_REAL_TYPE=float`. Длины измеряются в метрах, углы — в радианах. Сустав `k_dh_joint` содержит тип, `a`, `alpha`, `d_offset`, `theta_offset`. Используется стандартная DH-конвенция:

`A_i = Rz(theta_i) Tz(d_i) Tx(a_i) Rx(alpha_i)`.

Для `K_REVOLUTE`: `theta_i = theta_offset + joint_positions[i]`, `d_i = d_offset`. Для `K_PRISMATIC`: `theta_i = theta_offset`, `d_i = d_offset + joint_positions[i]`. Modified DH не поддерживается. Знаковые длины допустимы.

`k_transform.m[4][4]` хранится построчно и преобразует столбец координат из дочерней системы в родительскую. Последний столбец — перенос, верхний блок 3×3 — вращение. Последняя строка должна быть точно `(0, 0, 0, 1)`. Результат прямой кинематики:

`world_tool = world_base * A_1 * ... * A_n * last_tool`.

Ограничения координат суставов проверяет библиотека. Ограничения скорости, ускорения, момента и столкновения проверяет приложение.

## Модель и владение памятью

Приложение выделяет `k_model` и массив `k_joint_config` минимум на `n` элементов. Число суставов положительное; фиксированного предела 6 или 64 в ядре нет. Размеры, которые невозможно безопасно представить, отклоняются.

Настройка выполняется в следующем порядке:

1. `k_model_begin(model, storage, storage_capacity, joint_count)` обнуляет используемые элементы storage и переводит модель в `K_CONFIGURING`.
2. Для каждого сустава `k_model_set_joint(model, index, geometry)` копирует DH-геометрию, а `k_model_set_limits(model, index, limits)` задаёт ограничения.
3. `k_model_set_base(model, world_base)` и `k_model_set_tool(model, last_tool)` копируют преобразования. Единичные преобразования тоже задаются явно.
4. `k_model_finalize(model)` проверяет полноту и корректность конфигурации и при успехе переводит модель в `K_READY`.

`k_joint_limits` содержит `mode`, `min`, `max`. Для `K_BOUNDED` границы конечны и `min <= max`; равенство фиксирует координату сустава. Для `K_UNBOUNDED` границы игнорируются и setter сохраняет их как нули. Координаты на границах разрешены. Начальное приближение IK вне диапазона возвращает `K_JOINT_LIMIT`; автоматически обрезать его решатель не будет.

Модель заимствует массив storage, который должен жить дольше всех вызовов с этой моделью. Исходные структуры геометрии, ограничений и преобразований после setter-вызовов можно освобождать. Setter-функции работают только в `K_CONFIGURING`; повторная настройка начинается с `k_model_begin` и требует заново задать все параметры. Расчёты и `k_model_validate` требуют `K_READY` и повторно проверяют конфигурацию.

При параллельных вызовах модель и входные массивы должны оставаться неизменными, выходы и workspace должны быть отдельными для каждого вызова. Ядро не содержит изменяемого глобального состояния. Пересечение входных, выходных и рабочих областей запрещено, кроме явно разрешённого случая композиции ниже. Ёмкости измеряются в элементах, не в байтах; действительный размер и время жизни памяти обеспечивает вызывающий код.

Полный пример настройки — [forward_example.c](../examples/forward_example.c).

## Преобразования и прямая кинематика

| Функция | Действие |
| --- | --- |
| `k_transform_identity(out)` | Записывает единичное преобразование |
| `k_transform_validate(transform)` | Проверяет конечность, вращение и последнюю строку |
| `k_transform_compose(parent_mid, mid_child, out)` | Вычисляет произведение; out может точно совпадать с любым входом |
| `k_model_validate(model)` | Проверяет готовую модель без изменения данных |
| `k_forward(model, joint_positions, joint_count, world_tool)` | Вычисляет одну позу инструмента |
| `k_forward_frames(model, joint_positions, joint_count, frames, frame_capacity, workspace, workspace_capacity)` | Вычисляет все кадры через рабочий буфер |

Переданный `joint_count` должен равняться числу суставов модели. Все координаты должны быть конечными и удовлетворять заданным ограничениям. Для кадров нужны **два непересекающихся массива по n+2 преобразования**: выход и workspace. Индексы результата: `0` — база в мире, `1..n` — звенья в мире, `n+1` — инструмент в мире. Элементы за `n+2` не изменяются.

FK сохраняет выход при ошибке. При численном отказе workspace может содержать частичный расчёт: это не результат. Расчёт занимает O(n) времени и O(1) внутренней памяти. Для всех кадров внешняя память занимает `2*(n+2)*sizeof(k_transform)` байт. Для одной позы рабочий массив не нужен.

## Позиционная обратная кинематика

Подключите `<manipulator/inverse.h>`. Решатель ищет координаты суставов для целевой точки `k_vec3 target` в мировой системе. Ориентация инструмента не ограничивается. Начальное приближение задаёт старт локального поиска; ближайшее, единственное решение и глобальная сходимость не гарантируются.

```c
k_status k_ik_workspace_size(size_t joint_count, size_t *element_count);
k_status k_inverse_position(const k_model *model, const k_vec3 *target,
                            const k_real *initial_joint_positions, size_t joint_count,
                            const k_ik_options *options, k_real *workspace,
                            size_t workspace_capacity, k_real *joint_positions,
                            size_t output_capacity, k_ik_report *report);
```

`k_ik_workspace_size` возвращает необходимое число элементов `k_real`: сейчас `6*n`. При ошибке element_count сохраняется. Выходной массив joint_positions должен вмещать минимум `n` элементов. Workspace обязателен, даже если начальное приближение уже удовлетворяет допуску. Элементы буферов за необходимым размером не изменяются.

Все поля `k_ik_options` задаются явно:

| Поле | Значение и требования |
| --- | --- |
| `max_iterations` | Положительный предел попыток итерации |
| `max_backtracking_trials` | Положительный предел проб с уменьшением шага для каждого направления |
| `position_tolerance` | Конечный положительный допуск евклидовой ошибки позиции, метры |
| `length_scale` | Конечный положительный масштаб длины для нормализации, метры |
| `damping` | Конечный положительный коэффициент регуляризации нормализованной задачи |
| `joint_scales` | Массив из n конечных положительных масштабов координат: радианы для R, метры для P |
| `max_joint_steps` | Массив из n конечных положительных пределов изменения координат за шаг, в единицах сустава |
| `joint_count` | Должен совпадать с числом суставов модели и переданных координат |

Также требуется `max_backtracking_trials <= (SIZE_MAX-1)/2` и `max_iterations <= (SIZE_MAX-1)/(2*max_backtracking_trials)`, чтобы счётчики отчёта не переполнились. Универсальных параметров для всех роботов нет; [inverse_example.c](../examples/inverse_example.c) показывает конкретную 3R-модель и параметры для неё.

Метод использует позиционный якобиан и damped least squares (DLS). Нормализованный якобиан имеет столбцы `J_i * joint_scales[i] / length_scale`. Регуляризация может автоматически увеличиваться для численной устойчивости. Шаг масштабируется общим коэффициентом по max_joint_steps, пробные координаты ограничиваются диапазонами суставов. При неудаче DLS-направления проверяется градиентное направление. В каждом поиске коэффициент шага начинается с 1 и уменьшается вдвое.

`K_OK` означает, что найденные координаты удовлетворяют ограничениям, а вычисленная FK евклидова ошибка позиции не превышает position_tolerance. Только при успехе joint_positions получает результат. При любой ошибке он сохраняется; workspace может содержать промежуточные данные. `K_NO_CONVERGENCE` и `K_STALLED` не доказывают недостижимость цели.

Указатель report необязателен и может быть NULL. Если он задан, отчёт записывается **при любом статусе**, включая ошибки входных данных:

| Поле `k_ik_report` | Содержание |
| --- | --- |
| `termination` | Возвращённый статус |
| `iteration_attempts` | Число начатых итераций |
| `accepted_steps` | Число принятых шагов |
| `fk_evaluations` | Число вызовов FK, включая начальный и неудачные пробы |
| `jacobian_evaluations` | Число начатых вычислений якобиана |
| `residual` | Ошибка позиции начального приближения или последнего принятого шага, метры |
| `residual_valid` | Ненулевое значение означает, что residual вычислен и пригоден для чтения |
| `effective_damping` | Последнее вычисленное значение регуляризации в масштабе нормализованной задачи; 0, если ещё не вычислено |

Отчёт первоначально обнуляется; ошибки до успешной начальной FK оставляют residual_valid равным 0. Если начальное приближение уже подходит, выполняется одна FK и ноль итераций. Вычисления effective_damping могут предшествовать последующему численному отказу и не означают, что шаг принят.

За одну итерацию выполняются не более двух поисков по max_backtracking_trials проб; всего не более `1 + 2*max_iterations*max_backtracking_trials` вызовов FK. Верхняя оценка времени — O(n * max_iterations * max_backtracking_trials) плюс проверка входов и начальная FK; внутренняя память O(1), внешний workspace O(n). Ограничение итераций не заменяет измерения времени на конкретном МК.

## Статусы

| Статус | Код | Значение |
| --- | --- | --- |
| `K_OK` | 0 | Успех |
| `K_INVALID_ARGUMENT` | 1 | Обязательный указатель равен NULL |
| `K_INVALID_MODEL` | 2 | Недопустимое число, тип суставов или ограничения |
| `K_SIZE_MISMATCH` | 3 | Число координат/параметров не совпадает с моделью либо индекс вне диапазона |
| `K_BUFFER_TOO_SMALL` | 4 | Недостаточная ёмкость storage, выхода или workspace |
| `K_NONFINITE_INPUT` | 5 | Обязательный численный вход содержит NaN/Inf |
| `K_NUMERIC_ERROR` | 6 | Переполнение, непредставимый промежуточный результат или недопустимое вычисленное преобразование |
| `K_INVALID_TRANSFORM` | 7 | Конечная входная матрица не удовлетворяет контракту преобразования |
| `K_NOT_READY` | 8 | Вычисление или проверка модели в K_EMPTY либо K_CONFIGURING |
| `K_INVALID_STATE` | 9 | Недопустимое состояние модели или setter/finalize вне K_CONFIGURING |
| `K_INCOMPLETE_CONFIGURATION` | 10 | Не заданы все обязательные параметры модели |
| `K_JOINT_LIMIT` | 11 | Входная координата вне заданного диапазона |
| `K_INVALID_OPTIONS` | 12 | Недопустимые параметры IK |
| `K_NO_CONVERGENCE` | 13 | Исчерпан предел итераций IK |
| `K_STALLED` | 14 | Поиск IK остановился без принятого шага при наличии допустимой пробы |

Setter-функции и finalize сохраняют конфигурацию при ошибке; begin при ошибке сохраняет модель и storage. Преобразования и результаты FK/IK также сохраняются при ошибке. Исключения — рабочие буферы и отчёт IK, описанные выше.

Если нарушено несколько условий, порядок выбора ошибки не входит в API. Статус возвращается непосредственно, без протокола через errno и без печати сообщений. Контракт рассчитан на quiet NaN; обработка signaling NaN не обещается.

## Численный профиль и переносимость

Нужны IEEE binary32/binary64, округление к ближайшему, сохранение субнормальных чисел и обычный runtime libm без включённых ловушек floating point. Запрещены fast-math и finite-math-only; обнаруживаемые флаги отклоняются при сборке. Режимы FTZ/DAZ должен отключить вызывающий проект. Ограничения нельзя проверить только размерами C-типов; host-тесты и embedded-smoke проверяют выбранное окружение.

Допуск проверки вращений — `2e-12` для double и `2e-5` для float; он не применяется к последней строке. Матрицы не нормализуются автоматически. Длинные цепи могут завершиться контролируемой численной ошибкой из-за накопления округления. Диапазон математического runtime и точность сокращения аргументов ограничивают работу с огромными углами. [Отчёт валидации 0.1](validation.md) относится к исторической версии и не подтверждает характеристики новой IK.

Публичные имена функций отображаются через config.h на символы `k_v2_f64_*` или `k_v2_f32_*`. Используйте заголовки выбранной сборки: смена `K_USE_FLOAT` в приложении запрещена. Каждый профиль устанавливается в отдельный prefix, поскольку config.h и имя импортируемого target общие. Одновременное подключение двух профилей в один процесс пока не поддерживается. ABI разных компиляторов и платформ не гарантируется; структуры не являются форматом сериализации. API/ABI версии 0.2 несовместим с 0.1: прежняя k_model_init заменена обязательной поэтапной настройкой.

Для собственной embedded-сборки FK нужны `src/transform.c`, `src/model.c`, `src/dh.c`, `src/forward.c` и `src/internal.h`. Для IK дополнительно нужны `src/differential.c`, `src/linear3.c`, `src/inverse_dls.c`, `src/inverse.c` и `src/inverse_internal.h`. В обоих случаях нужны публичные заголовки и config.h выбранного профиля; C11, libm и memcpy/memset предоставляет toolchain. Startup, linker script и реакция на ошибку принадлежат приложению. Ядро не требует GoogleTest, C++, Python, POSIX или heap.
